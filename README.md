# Xposure

**Xposure is an accessible portfolio exposure graph that reveals hidden relationships across asset classes.**

Instead of showing a portfolio only as allocations and percentages, Xposure maps how holdings can still be economically connected underneath — across public equity, private equity, real estate, private credit, and infrastructure.

The goal is simple: make hidden concentration easier to understand, both visually and through audio.

---

## Why Xposure?

A portfolio can look diversified on paper while still having overlapping economic exposure.

For example, a utilities holding may appear unrelated to semiconductors, while data-center demand can connect the two through power infrastructure, capital spending, and supply-chain dependencies.

Xposure turns those relationships into an interactive knowledge graph so users can see how different assets connect and where concentration risk may exist.

---

## Features

- Interactive cross-asset portfolio graph
- Asset class encoded by node shape
- Sector encoded by color
- Exposure relationships encoded through different edge styles
- Backend-generated hidden concentration insights
- Contributing holdings highlighted directly on the graph
- Natural-language portfolio questions with text + spoken answers
- Keyboard-only graph navigation
- Audio narration and sonification for blind and low-vision users
- Pitch maps to sector, while stereo position maps to graph position
- **Multi-hop exploration**: expand the graph 1–3 hops past your holdings to
  see assets you don't own but are exposed to
- **Path finder**: every route between two assets, including ones that run
  through companies outside the portfolio
- **Multi-hop themes**: theme concentration once relationships are followed
  several hops deep, with the "hidden" exposure one-hop analysis misses
- **Shock scenarios**: stress one asset and see which holdings sit within
  reach of it, and how much of the portfolio that is
- **Add your own data**: create portfolios, add companies, hold them at a
  weight (others rebalance automatically) and draw connections
- **Connection agent**: an LLM tool loop that researches the graph and drafts
  new companies and relationships as *proposals* for a person to approve
- **Two layouts**: a dense dark *Workspace* (rail, graph, inspector) and the
  original light *Canvas*, switchable at any time

The accessibility experience is built into the same graph rather than being a separate mode or alternate interface.

## Architecture

```text
Curated Portfolio Data
        ↓
Tiger Data / PostgreSQL
        ↓
Python Insight Logic
        ↓
FastAPI
        ↓
Snowflake Cortex
        ↓
ElevenLabs
        ↓
React + TypeScript
```

The seeded relationships are curated rather than generated by an LLM. When the
connection agent is used, the model only *drafts*: everything it writes is
stored as a proposal (`status = proposed`, `source = agent`, with a
confidence score) and stays out of the graph, insight, and Q&A until a person
approves it in the Review panel.

### Multi-hop model

Exposure edges read "A is exposed to B". `app/network.py` holds the pure
traversal logic:

- **Themes** follow edges forward. An edge reached at hop *k* carries its
  theme at strength `decay^(k-1)` (default 0.5); each holding counts once per
  theme through its strongest route. With one hop this equals the original
  insight exactly (that equivalence is tested).
- **Paths, depth expansion and shocks** treat edges as undirected, because a
  shock can travel either way along a dependency.

This is a structural map of curated relationships, not a risk model.

## Accessibility

Xposure includes an audio-visual exploration mode designed for blind and low-vision users.

Users can:

- navigate holdings entirely with the keyboard
- hear portfolio and risk narration
- trigger sonification by hover, click, or keyboard navigation
- hear sector information through pitch
- hear spatial graph position through stereo panning
- use screen-reader-friendly labels and live regions

A full VoiceOver/NVDA validation pass is still planned.

## Running Locally

### Backend

```bash
python -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
python -m scripts.create_schema   # creates tables and upgrades older databases
python -m scripts.seed            # resets to the three demo portfolios
uvicorn app.main:app --reload
```

`create_schema` is safe to re-run: it adds the `companies` table and the new
exposure columns to a database created by an earlier version.

The connection agent uses Snowflake Cortex (same `SNOWFLAKE_*` settings as
narration) through its OpenAI-compatible tool-calling API. To use another
OpenAI-compatible endpoint set `AGENT_BASE_URL`, `AGENT_API_KEY` and
`AGENT_MODEL`. Without either, everything except the agent still works and
the Agent panel says what is missing.

Backend runs at:

```text
http://localhost:8000
```

### Frontend

```bash
cd frontend
npm install
npm run dev
```
